# 交互节点倒放时间线审计

## 结论

已复现用户报告。当前播放机制让每个 `AnimationAction` 自行计时并在各自片段末尾停住，收起仅设置各动作 `timeScale=-1` 并解除暂停。因此，结束时间不同的运动构件从各自末尾同时开始倒放，不能重现整个模型统一时间线的逆序过程。

审计阶段仅核实原因、影响及方案。用户随后授权修复，修复结果记录在文末；原始 GLB 未改动。

## 实测证据

新节点 `high-low-roof-joint-01` 完全展开后：

| 构件 | 片段时长 | 倒放开始后同一帧的动作时刻 |
| --- | ---: | ---: |
| 附加卷材、防水层等 | 4s | 3.736s |
| 砖砌矮墙、低屋面结构板 | 1.0417s | 0.7777s |
| 抹灰 | 1s | 0.736s |
| 高墙（静止） | 0.0417s | 0s |

可见矮墙、结构板和抹灰并未处于主时间线的3.736秒位置，而是已经开始自身的复原运动。正确行为是在主时间线从4秒倒退到各短片段终点之前保持终态，再继续逆序运动。

定位：

- `src/components/viewer/ModelViewer.tsx:288`：按源片段时长建立动作，`LoopOnce` 与 `clampWhenFinished` 让短片段提前暂停。
- `src/components/viewer/animationController.ts:89`：倒放仅对各动作设置负速率并解除暂停，没有统一时间定位。
- `src/components/viewer/ModelViewer.tsx:302`：最长片段仅用于进度显示和结束判定，没有统一其他动作时钟。

## 影响范围

读取已注册且启用动画的30个单模型节点，检查源GLB片段时长及短片段轨道的实际数值变化：

- 26个节点包含不同长度的片段。
- 其中24个只是静止基座短片段与4秒运动片段的组合，未发现运动短片段造成的复原顺序问题。
- 2个节点具有实际变化的短片段，确认受到影响：
  - 高低屋面变形缝（一）：矮墙、抹灰、低屋面结构板。
  - 构造柱：对象01、02、03、04，片段结束时刻分别约3.5417、0.9167、1.7917、2.6667秒。
- 多模型节点的算法分解与静态节点不经过本次问题代码路径。

## 次要发现

`src/NodeDetail.tsx:47,178` 将进度条百分比固定换算为4秒。当前上述30个节点的最长片段均为4秒，因此现有资源未受此问题影响；未来导入其他时长动画会出现定位误差。应与主时间线时长一起修正。

## 建议修复与验证

1. 播放、倒放、拖动和重置统一使用模型主时间轴，长度取所有源片段结束时刻的最大值。
2. 保留原关键帧时刻与原运动速度。可将运行时克隆片段的播放长度统一延长至主时间线末尾，使短轨道到终点后保持姿态；不要拉伸关键帧或改写源GLB。
3. 中途切换展开/收起时从当前统一时刻继续，避免跳变；进度条读取真实总时长。
4. 使用真实Three.js混合器验证不同时长、静止片段、延迟开始的片段、往返中途切换、拖动与R重置。核心断言：同一主时间时刻的正放与倒放构件姿态一致。
5. 回归构造柱、新变形缝、现有4秒蓄水屋面，以及静态/多模型节点；保留首页画布、相机与侧栏状态检查。
