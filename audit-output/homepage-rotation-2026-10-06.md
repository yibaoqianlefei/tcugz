# 首页模型旋转审计与优化

日期：2026-10-06。范围：首页构造节点展示的五个模型。仅本地修改，未提交或部署。

## 发现

1. 首个模型包含14个网格和14个独立轮廓对象，每帧29次绘制。轮廓线均位于原表面上，没有深度偏移，并以透明、写入深度的方式绘制。这同时存在表面深度竞争、透明排序变化及额外绘制负载的问题。
2. 相机近远裁剪范围约为0.01至8.72，比例约872:1。对于薄屋面层和共面轮廓，其深度精度明显差于围绕实际模型设定的范围。
3. 本项目的Drei OrbitControls调用three-stdlib控制器，其自动旋转步长按固定60次更新/秒计算，并未使用实际帧时长。帧率波动时，旋转的单位时间速度也随之变化。
4. 高像素密度屏幕按1.5倍分辨率持续绘制。已有画面离屏及切换功能板块时的暂停逻辑，但没有显式处理浏览器页面隐藏。

## 本地调整

- 首页静态模型的原有轮廓几何转至同一模型坐标系，合并成一个线对象；保持原轮廓阈值与全部线段。
- 轮廓不再进入透明排序队列，且不写入深度；对首页独立克隆的实体材质设置轻微多边形深度偏移，避免线与实体共面竞争。
- 近远裁剪面根据模型包围球与完整缩放范围设定，首个模型约为1.20至5.56，比例约4.63:1。不改变模型尺寸、初始正面方向或缩放限制。
- 在Drei控制器更新前，根据实际帧时长校正自动旋转步长和阻尼。限制隐藏恢复等长间隔的单步推进，避免重新出现画面后突跳。
- 像素密度上限固定为1.25，保留抗锯齿；在高像素密度设备上，像素工作量相对1.5上限减少约31%，不在旋转期间动态调整分辨率。
- 请求高性能WebGL设备；页面隐藏时停止持续渲染，恢复可见时继续。仍保留既有离屏及功能板块切换暂停逻辑。
- 材质克隆和合并轮廓在模型切换时释放；共享GLTF几何、源材质与贴图不修改，完整节点工作台不使用本次首页专用设置。

## 对比测量

测试条件：同一Playwright Chromium环境、1440×1000视窗、设备像素比1.5、Vite开发页面；首个模型连续采集180个已绘制帧。

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 每帧绘制调用 | 29 | 16 |
| 轮廓对象 | 14 | 1 |
| 模型三角形 | 2008 | 2008 |
| 轮廓线段 | 1131 | 1131 |
| 实际渲染像素比 | 1.5 | 1.25 |
| 帧间隔中位数 | 47.7ms | 42.3ms |
| 帧间隔95百分位 | 56.1ms | 56.4ms |
| 单位时间旋转速度的变异系数 | 0.135 | 0.025 |

绘制调用减少约45%；此环境的帧间隔中位数改善约11%，长帧尾部没有改善。旋转推进的时间一致性改善明显。该自动化浏览器结果不能代表用户设备帧率，也不能据此保证60fps；此次确认的优化是绘制负载、深度冲突条件和帧率相关转速。

原始数据：`tmp/homepage-rotation-baseline.json`、`tmp/homepage-rotation-optimized.json`；测量脚本位于 `tmp/audit-homepage-rotation.mjs` 与 `tmp/audit-homepage-rotation-optimized.mjs`。
